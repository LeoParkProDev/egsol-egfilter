# 전환 추적 + 유입 경로 기록 — 설계

목적: 광고를 다시 돌릴 때 "문의가 몇 건, 어느 키워드·경로에서" 왔는지 **숫자로** 보이게 한다. 구매가 아니라 **문의(리드)** 를 전환으로 센다.

## 1. 구성

```
방문자 랜딩 ──▶ 유입 파라미터 캡처(sessionStorage) ──▶ 견적 폼 hidden 필드 ──▶ 메일 본문에 "유입 경로"
            └─▶ GA4 / 네이버 프리미엄 로그분석 스크립트 (ID 있을 때만 주입)
                     ▲
    클릭 이벤트 위임: tel: / pf.kakao.com / smartstore.naver.com 링크 → 이벤트
    폼 성공·폴백 → 이벤트 + 네이버 전환(cnv)
```

## 2. 파일

| 파일 | 역할 |
|---|---|
| `app/data/site.ts` | (변경 없음) |
| `app/lib/analytics.ts` | `track(event, params)`, `captureAttribution()`, `getAttribution()` — 순수 함수 + window 가드 |
| `app/components/Analytics.tsx` | `"use client"`. GA4·네이버 스크립트 주입(`next/script`, `afterInteractive`), 마운트 시 `captureAttribution()`, `document` 클릭 위임 리스너 등록 |
| `app/layout.tsx` | `<Analytics />` 한 줄 추가 (body 하단) |
| `app/quote/QuoteForm.tsx` | hidden `source`·`landing`·`keyword` 필드(getAttribution 값), 성공 시 `track("quote_submit")` + 네이버 cnv, 폴백 시 `track("quote_fallback", {method})` |
| `app/api/quote/route.ts` | `source`·`landing`·`keyword` 수신 → 메일 본문에 "유입 경로" 블록 |
| `.env.example` | `NEXT_PUBLIC_GA_ID`, `NEXT_PUBLIC_NAVER_WCS_ID` 추가 |
| `docs/전환추적-설정.md` | ID 발급·등록·검증 절차 (사장님용) |

## 3. 유입 파라미터 캡처

첫 랜딩 시 1회, `sessionStorage["eg_attr"]`에 JSON 저장. 이미 있으면 덮어쓰지 않는다(세션 내 첫 유입이 기준).

```ts
interface Attribution {
  source: string;   // 아래 규칙으로 판정
  keyword: string;  // n_query 또는 utm_term, 없으면 ""
  landing: string;  // pathname (쿼리 제외)
  referrer: string; // document.referrer 호스트만
  ts: string;       // ISO
}
```

`source` 판정 순서:
1. `n_media` 또는 `n_query` 파라미터 있음 → `"naver-ad"` (네이버 검색광고 기본 파라미터)
2. `utm_source` 있음 → 그 값 (`utm_medium` 있으면 `source/medium`)
3. `gclid` 있음 → `"google-ad"`
4. referrer 호스트가 `naver.com` 계열 → `"naver-organic"`, `google.` → `"google-organic"`, `kakao` → `"kakao"`
5. referrer 없음 → `"direct"`
6. 그 외 → referrer 호스트

**개인정보**: 파라미터 값 그대로 저장하되 이름·전화 같은 값은 애초에 URL에 없다. 분석 툴에는 `source`·`keyword`·`landing`만 보내고 폼 입력값은 절대 보내지 않는다.

## 4. 이벤트 정의

| 이벤트 | 트리거 | 파라미터 | 네이버 전환 |
|---|---|---|---|
| `quote_submit` | `/api/quote` 200 응답 | source, keyword, landing, has_photo | `wcs.cnv("4","1")` (신청/예약) |
| `quote_fallback` | share/mailto/copied 경로 진입 | method, source, landing | `wcs.cnv("4","1")` |
| `kakao_click` | `a[href*="pf.kakao.com"]` 클릭 | page, source | `wcs.cnv("5","1")` (기타) |
| `phone_click` | `a[href^="tel:"]` 클릭 | page, source | `wcs.cnv("5","1")` |
| `smartstore_click` | `a[href*="smartstore.naver.com"]` 클릭 | page, source | 없음 |

클릭 위임은 `document.addEventListener("click", …, {capture:true})` 하나로 처리한다 — 컴포넌트마다 손대지 않는다. `closest("a")`로 앵커를 찾고 href로 분기.

GA4: `window.gtag?.("event", name, params)`. 네이버: `window.wcs && (_nasa["cnv"] = wcs.cnv(type, "1"), wcs_do(_nasa))`. 둘 다 없으면 조용히 무시 — **분석 ID가 없어도 사이트는 정상 동작**해야 한다.

## 5. 스크립트 주입

- `NEXT_PUBLIC_GA_ID`(예: `G-XXXXXXX`)가 있을 때만 gtag.js + config 주입. `send_page_view: true`.
- `NEXT_PUBLIC_NAVER_WCS_ID`가 있을 때만 `//wcs.naver.net/wcslog.js` + `wcs_add["wa"]="ID"; wcs_do();` 주입.
- App Router는 클라이언트 라우팅이라 페이지 전환 시 GA page_view가 자동으로 안 잡힌다 — `usePathname()` 변화마다 `gtag("event","page_view",{page_path})`를 쏜다. 네이버는 `wcs_do()` 재호출.
- 스크립트는 `strategy="afterInteractive"`. 렌더 블로킹 금지.

## 6. 메일 본문 추가 블록 (route.ts)

```
유입 경로: naver-ad

```
값이 전부 비면 `유입 경로: (미확인)` 한 줄만.

## 7. 폼 hidden 필드

`QuoteForm` 마운트 시 `getAttribution()`으로 채운다. `name="source" | "landing" | "keyword"`. 서버에서 `str()`로 정리, 각 200자 제한.

## 8. 사장님용 설정 문서 (`docs/전환추적-설정.md`)

1. GA4: analytics.google.com → 속성 만들기 → 웹 스트림 → 측정 ID `G-…` → Vercel 환경변수 `NEXT_PUBLIC_GA_ID`
2. 네이버: 검색광고 시스템 → 도구 → 프리미엄 로그분석 → 사이트 등록 → 공통 스크립트의 `wcs_add["wa"]="…"` 값 → `NEXT_PUBLIC_NAVER_WCS_ID`
3. Redeploy
4. 검증: GA4 실시간 보고서에서 본인 접속 확인 → 견적 폼 테스트 제출 → `quote_submit` 이벤트 확인. 네이버: 로그분석 "전환" 리포트에 1건 잡히는지(반영 지연 있음)
5. 광고 캠페인 URL에 `?n_media=…&n_query=…`는 네이버가 자동으로 붙인다(추적 URL 옵션 ON 확인). 구글·기타는 `utm_source=…&utm_term=…` 수동.

## 9. 검증 (워커가 수행)

- `npx tsc --noEmit`, `npx eslint app`, `npm run build` 모두 통과
- ID 없이 빌드한 HTML에 `gtag`·`wcslog` 문자열이 **없어야** 함 (`grep -c` = 0)
- `NEXT_PUBLIC_GA_ID=G-TEST NEXT_PUBLIC_NAVER_WCS_ID=abc npm run build` 후 HTML에 둘 다 **있어야** 함
- 로컬 `next start`로 `/api/quote`에 `source=naver-ad&keyword=수술실 헤파필터&landing=/medical/operating-room`를 실어 POST → (env 없으면 503이므로) 가짜 GMAIL 자격증명으로 띄워 500 SEND_FAILED까지 가는지, 그리고 route가 필드를 파싱해 본문에 넣는지는 **단위 함수로 분리해 테스트** (`buildMailText()` 순수 함수로 뽑아 node로 호출)
- 브라우저 없이 클릭 위임 로직은 순수 함수 `classifyAnchor(href) → event|null`로 분리해 node에서 검증

## 10. 하지 말 것

- 폼 입력값(이름·전화·이메일·문의 내용)을 GA/네이버에 보내지 않는다
- 분석 ID를 코드에 하드코딩하지 않는다
- 기존 컴포넌트의 링크 마크업을 이벤트 때문에 바꾸지 않는다 (위임으로 해결)
- push 하지 않는다 (커밋만. 계정 전환이 필요해 푸시는 상위에서)
