# 스마트스토어 주문 유입을 위한 검색 경로

## 변경 내용

`/products`를 네 제품군과 현재 등록된 규격으로 연결되는 서버 렌더링 허브로 구성했다. 제품 상세와 규격 페이지를 크롤러가 일반 링크로 따라갈 수 있고, 푸터와 사이트맵에서도 허브를 찾을 수 있다. 롤필터는 프레임형 가로×세로×두께 표기와 구분해 두께·폭·길이 기준으로 안내한다.

허브와 상세 페이지에는 페이지 식별용 BreadcrumbList, ItemList를 제공한다. 제품·규격 상세의 JSON-LD에 실제 가격이나 재고를 추가하지 않으며, 구매 조건은 스마트스토어에서 확인하도록 안내한다. 확인되지 않은 수정일을 사이트맵에 현재 시각으로 채우지 않고, 날짜가 원본 데이터에 있는 가이드 항목만 `lastModified`를 유지한다.

## 확인 방법

배포된 사이트 또는 실행 중인 로컬 서버의 기본 URL을 인자로 전달한다.

```sh
node scripts/check-store-seo.mjs https://evergreen-filter.vercel.app
```

Node 24 이상이 필요하다. QA 스크립트는 Node 내장 TypeScript 지원으로 `app/data/store-catalog.ts`와 `app/data/sizes.ts`의 실제 내보내기를 읽는다.

스크립트는 허브의 네 제품군 링크와 고유 규격 링크 23개, 관련 사이트맵 항목, 제품·규격 페이지의 정확한 canonical·제목·설명·H1을 확인한다. 페이지 상단 CTA는 placement와 가족별 카테고리 href를 검사한다. 단일 규격에 코드가 연결된 경우에는 해당 규격의 유일한 variant code 및 `storeCatalogByCode`의 검증된 URL과 모두 일치해야 직접 상품 URL을 통과시킨다. 각 `size_variant` 링크도 코드가 있으면 해당 variant와 카탈로그 URL을 대조하고, 코드가 없는 항목은 제품군 카테고리로 연결되어야 한다. JSON-LD는 파싱 가능 여부와 `offers` 필드 유무를 검사한다.

현재 검증된 직접 URL 매핑은 33개다. B_ALL 롤 4개 옵션은 같은 판매 페이지로 연결되므로 구매자가 스마트스토어에서 알맞은 옵션을 직접 선택해야 한다. 중지된 개별 상품 URL은 매핑에 넣지 않았으며, 직접 링크로 허용하지 않는다. 상품 ID를 추정해 URL을 만들지 않는다.

## 검색 표시 관련 근거

- 네이버 서치어드바이저는 페이지 주제와 내용을 설명하는 제목·설명, 사이트 구조와 수집 가능한 링크 구성을 검색 최적화 기본으로 안내한다: [네이버 검색 최적화 가이드](https://searchadvisor.naver.com/guide/seo-help).
- Google은 구조화 데이터가 검색 결과 표시를 보장하지 않으며, Product 결과에는 실제 페이지 내용과 일치하는 상품 정보가 필요하다고 안내한다. 이 사이트는 판매 가격·재고를 확인할 수 없으므로 해당 오퍼 필드를 만들지 않는다: [Google Product structured data](https://developers.google.com/search/docs/appearance/structured-data/product).

## 성과 측정 범위

페이지의 스마트스토어 링크 클릭은 외부 이동 신호일 뿐 주문 건수가 아니다. 실제 성과는 판매자센터에서 확인 가능한 취소 제외 주문으로 판단해야 한다. 이번 작업만으로 검색 순위, 유입 증가 또는 주문 증가를 주장하지 않는다.
